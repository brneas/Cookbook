# Security policy

## Supported versions

Security fixes target the latest published **1.x** release. Until 1.0.0 is published, there is no supported stable release. Older development builds are not supported for security updates.

## Report privately

Use this GitHub repository's **Security → Report a vulnerability** (private vulnerability reporting). Repository maintainers must enable this feature before publication. If the private reporting control is unavailable, do not disclose the vulnerability in a public issue; request a private reporting channel without technical exploit details.

Include affected versions, impact and minimal reproduction steps using synthetic data. Do not include passwords, app passwords, Login Flow or polling tokens, Authorization headers, keystores, secure-storage contents, private server logs or private recipe exports. Redact hostnames and personal information when not necessary to understand the problem.

Allow maintainers a reasonable opportunity to investigate and prepare a fix before public disclosure. Coordinate disclosure timing in the private report. Do not access other users' accounts or data, disrupt services or test against servers without permission. No response-time guarantee or bounty program is offered.
